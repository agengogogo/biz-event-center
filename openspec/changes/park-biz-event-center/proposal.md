# Proposal

## Why

园区内 IoT 设备、门禁通行、能耗设施、停车车辆、视频安防及第三方系统持续产生大量异构事件，缺乏统一的接入、标准化、分发与审计手段，导致告警响应慢、事件无法沉淀复用、运营态势不可见。需要一个统一的园区业务事件中心，把各类事件标准化汇聚，并驱动订阅、通知与运营监控。

## What Changes

- 新增多源事件接入与标准化：接收 IoT 设备、门禁/人员通行、能耗/设施、停车/车辆、视频/安防、第三方业务系统上报的事件，以及通过管理 API（管理前端表单是其客户端之一）直接创建的事件，统一转换为规范事件模型。
- 新增事件分发/总线：按主题与订阅规则路由并可靠投递事件，支持失败重试与死信处理。
- 新增规则与订阅管理：订阅及其过滤/转换规则的创建、启停与生命周期管理。
- 新增通知推送：短信、企业微信、Webhook、邮件等通道，模板渲染与投递结果跟踪。
- 新增事件存储与查询审计：事件持久化、条件检索、处理轨迹与审计记录。
- 新增运营监控大屏：事件统计聚合、实时态势与看板数据服务。
- 前后端解耦与 API 优先：后端以 REST API 为一等交付物，创建事件、分发/重投事件、订阅与通知管理、事件查询、看板数据均可通过 API 直接操作，管理前端仅作为 API 客户端之一。
- 交付形态为后端服务（Java + Spring Boot）加管理前端；后端 API 独立可用，管理前端可替换。
- 新增运行时后端适配层与本地演示 profile：将关系库、事件总线与幂等/缓存抽象为可插拔端口；生产沿用 PostgreSQL + Kafka + Redis，本地 PC 演示通过本地配置切换到嵌入式 SQLite（含 SQLite 持久化的发件箱/死信队列与幂等表），无需启动外部中间件，且对外 API 行为与生产一致。
- 新增业务事件类型注册表与负载契约：预置园区典型业务事件类型（IoT 设备、门禁/人员通行、能耗/设施、停车/车辆、视频/安防、第三方系统、人工），每种类型可定义其 payload JSON Schema，并提供管理 API 维护类型定义；接入时识别业务事件类型并按 schema 校验负载，校验结果为非阻塞并随事件记录。

## Capabilities

### New Capabilities

- `event-ingestion`: 多源园区事件的接收、校验、去重与标准化为规范事件模型，含通过 API（含管理前端表单）手工创建事件。
- `event-dispatch`: 事件总线，按主题/订阅匹配路由并可靠投递，含重试与死信，并支持通过 API 直接触发分发与重投。
- `event-subscription`: 订阅及其过滤/转换规则的配置与生命周期管理。
- `event-notification`: 通知通道、模板渲染、推送与投递结果跟踪。
- `event-store-query`: 事件持久化、条件检索、时间线轨迹与审计。
- `event-ops-dashboard`: 事件统计聚合、实时态势，以及与客户端无关的看板数据 API。
- `runtime-profiles`: 通过可插拔基础设施端口与运行时配置，在生产后端（PostgreSQL/Kafka/Redis）与本地嵌入式后端（SQLite）之间切换，并保持对外 API 行为一致。
- `event-type-registry`: 业务事件类型定义与每种类型的 payload 契约管理，含预置园区典型类型目录与查询接口。

### Modified Capabilities

- 无（当前项目尚无既有 spec）。

## Impact

- 新增后端服务与管理前端两大部分，仓库从空脚手架变为实际工程。
- 引入基础设施依赖：消息中间件（事件总线）、关系型数据库、缓存，以及可选的对象存储/检索组件。
- 所有能力通过统一的、版本化的 REST API（OpenAPI 描述）暴露，管理前端仅消费公开 API，前后端可独立部署与演进；API 需要鉴权与多园区数据隔离。
- 前后端解耦：前端不依赖后端私有接口，后端 API 可被脚本或第三方客户端直接调用，完成事件创建与分发。
- 规范事件模型成为接入、分发、存储、通知、看板各能力之间的跨能力契约。
- 需要可观测性（指标、日志、链路）与部署编排（本地容器化）。
- 在 `common` 引入基础设施端口/适配器：事件总线端口（Kafka 适配器 + SQLite 发件箱适配器）、幂等端口（Redis 适配器 + SQLite 适配器），以及按 profile 的持久化（数据源、Hibernate 方言、Flyway 迁移位置）。
- 新增本地运行配置与一键启动方式，文档需说明本地演示无需 Docker/外部中间件。
- 新增 `event_type` 表与两套方言迁移（含预置目录种子）、引入 JSON Schema 校验器（draft 2020-12）、`IngestionService` 增加类型识别与负载校验、事件持久化/轨迹新增校验状态字段、OpenAPI 与接入文档更新。
