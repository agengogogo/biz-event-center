# Spec Delta

## Purpose

将规范事件按主题与订阅规则路由并可靠投递到订阅方，支持通过 API 直接触发分发与重投，在失败时重试并在无法恢复时进入死信，保证事件不丢失。

## ADDED Requirements

### Requirement: 按主题与订阅路由

系统 MUST 依据事件类型/主题将规范事件路由到匹配的订阅投递目标。

#### Scenario: 按主题匹配订阅并投递

- **WHEN** 规范事件发布且存在匹配该事件主题的启用订阅
- **THEN** 系统将事件投递到该订阅配置的目标

### Requirement: 可靠投递与重试

系统 MUST 在投递失败时按配置的退避策略重试，并在达到最大重试次数后把事件写入死信并记录失败原因。

#### Scenario: 投递失败后重试

- **WHEN** 向订阅目标的投递失败
- **THEN** 系统按配置的重试策略重新投递该事件

#### Scenario: 超过最大重试进入死信

- **WHEN** 投递在达到最大重试次数后仍然失败
- **THEN** 系统将该事件移入死信并记录失败原因

### Requirement: 投递有序与幂等

系统 MUST 支持为同一订阅目标配置有序投递，并依据事件标识对重复投递做幂等处理。

#### Scenario: 重复投递只生效一次

- **WHEN** 同一事件被重复投递到同一订阅目标
- **THEN** 系统依据事件标识保证该目标只生效一次

### Requirement: API 触发分发与重投

系统 MUST 允许调用方通过管理 API 对指定事件触发分发或重投，不依赖管理前端，并返回可查询的分发受理结果。

#### Scenario: 通过 API 触发分发

- **WHEN** 调用方通过管理 API 请求对某条已受理事件触发分发
- **THEN** 系统按订阅匹配执行路由与投递并返回受理结果

#### Scenario: 通过 API 重投失败事件

- **WHEN** 调用方通过管理 API 请求对某条投递失败的事件重投
- **THEN** 系统重新执行该事件的分发投递
