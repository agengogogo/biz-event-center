# Spec Delta

## Purpose

接收园区各来源的事件，完成校验、去重并标准化为统一的规范事件模型，为分发、存储与通知提供一致的事件输入。

## ADDED Requirements

### Requirement: 多源事件接入

系统 MUST 提供统一接入接口，接收来自 IoT 设备、门禁/人员通行、能耗/设施、停车/车辆、视频/安防、第三方业务系统的事件，以及通过管理 API 直接创建的事件。

#### Scenario: 已注册来源上报事件被接收

- **WHEN** 一个已注册且凭证有效的来源通过接入接口上报事件
- **THEN** 系统接收该事件并返回受理确认

#### Scenario: 未注册或凭证无效的来源被拒绝

- **WHEN** 未注册来源或凭证无效的请求上报事件
- **THEN** 系统拒绝该请求并返回未授权错误

### Requirement: 事件标准化

系统 MUST 将各来源的原始事件转换为规范事件模型，模型至少包含事件标识、事件类型、来源、发生时间、严重级别、园区/位置和负载字段，并保留原始负载。

#### Scenario: 异构负载被标准化

- **WHEN** 来源上报的字段结构与规范事件模型不一致
- **THEN** 系统将其映射为规范字段并保留原始负载

### Requirement: 事件校验与去重

系统 MUST 对入站事件执行必填字段与取值校验，并基于事件标识对重复上报进行幂等去重。

#### Scenario: 缺少必填字段被拒绝

- **WHEN** 入站事件缺少事件类型或发生时间
- **THEN** 系统拒绝该事件并返回校验错误

#### Scenario: 重复事件被去重

- **WHEN** 携带相同事件标识的事件被重复上报
- **THEN** 系统只受理一次并忽略后续重复

### Requirement: API 创建事件

系统 MUST 允许调用方通过管理 API 直接创建规范事件；管理前端表单是该 API 的客户端之一，手工创建的事件与来源事件使用相同的规范事件模型并进入一致的分发流程。

#### Scenario: 通过 API 直接创建事件

- **WHEN** 调用方通过管理 API 提交一条事件创建请求
- **THEN** 系统创建规范事件并进入与来源事件一致的分发流程

#### Scenario: 管理前端通过同一 API 创建事件

- **WHEN** 管理人员在管理前端表单中提交事件
- **THEN** 前端通过同一管理 API 创建事件，系统不区分请求来自前端还是其他客户端

### Requirement: 业务事件类型与负载校验

系统 MUST 在接入时依据事件类型注册表识别业务事件类型并以其 payload schema 校验负载。校验为非阻塞：类型未注册、已停用或负载不合规时事件仍被受理，但系统 MUST 记录校验结果（已校验/未校验及原因）以供查询与审计。

#### Scenario: 已注册类型且负载合规

- **WHEN** 入站事件的类型已注册且负载通过其 schema 校验
- **THEN** 系统受理该事件并将其校验结果标记为已校验

#### Scenario: 负载不合规仍被受理并标记未校验

- **WHEN** 入站事件的类型已注册但负载不满足其 schema
- **THEN** 系统仍受理该事件并记录未校验及原因

#### Scenario: 未注册或停用类型仍被受理并标记未校验

- **WHEN** 入站事件的业务事件类型未注册或已停用
- **THEN** 系统仍受理该事件并记录该类型未注册或已停用
