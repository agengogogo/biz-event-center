# Spec Delta

## Purpose

持久化规范事件及其处理状态，提供条件检索、时间线轨迹与审计能力，使事件可追溯、可复核。

## ADDED Requirements

### Requirement: 事件持久化

系统 MUST 持久化所有受理的规范事件及其分发、通知和处理状态。

#### Scenario: 事件可被持久化与读取

- **WHEN** 一个规范事件被受理
- **THEN** 系统将其持久化并可按唯一标识检索到

### Requirement: 事件条件检索

系统 MUST 支持按时间范围、事件类型、来源、严重级别和园区/位置等条件检索事件。

#### Scenario: 按时间范围与类型检索

- **WHEN** 用户按时间范围与事件类型发起查询
- **THEN** 系统返回满足条件的事件列表

### Requirement: 事件轨迹与审计

系统 MUST 记录事件从接入到分发和通知的处理轨迹，并保留可审计的操作与状态变更记录。

#### Scenario: 查看事件完整轨迹

- **WHEN** 用户打开某个事件的详情
- **THEN** 系统展示该事件从接入到分发和通知的完整处理轨迹

### Requirement: 事件类型与校验状态可查询

系统 MUST 在事件详情与处理轨迹中暴露其业务事件类型及负载校验状态（已校验/未校验及原因）。

#### Scenario: 查看事件的校验状态

- **WHEN** 用户打开某个事件的详情或轨迹
- **THEN** 系统展示该事件的业务事件类型识别与负载校验状态及原因
